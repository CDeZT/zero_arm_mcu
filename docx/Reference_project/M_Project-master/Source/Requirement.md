## 二、电机能力说明（重要）

✅ ZDT_X57S 闭环步进电机几乎涵盖所有闭环步进电机功能：
- 位置控制、速度控制、转矩控制、电流控制
- 过载保护、过热保护、堵转保护

✅ 电机有 5 种应答模式（见说明书 4.1.2 节），**本项目必须使用 Both 模式**：
- 收到命令时返回 02（确认收到）或 E2/EE（拒绝）
- 动作完成时返回 9F（到位/回零完成）

✅ 电机支持"定时返回信息"功能（见说明书 5.5.1 节），可周期性主动上报：
- 实时位置（功能码 0x36）
- 实时转速（0x35）
- 相电流（0x27）
- 电机状态标志（0x3A）
- 回零状态 + 电机状态（0x3C）

✅ 因此主控的职责是：
- 与上位机通信（接收指令、上报状态/数据）
- 与电机通信（发命令、解析多种应答）
- **作为双向消息中介，把三方的信息正确串起来**

## 四、⚡ 核心交互模型（必须严格实现）

> 这是本项目最重要的部分。Agent 必须在动手前完全理解，并在实现中逐条对应。

主控的本质角色是 **双向消息中介**，承担三条完整的"问答链"。
**任何一条链未完整实现，本项目就不算合格。**

### 4.0.1 链路 A：上电自动初始化与回零

```
上电
 → 主控初始化外设
 → 主控配置电机：Response = Both（必须）
 → 主控配置电机：启用定时返回（推荐每 100ms 上报位置和状态）
 → 主控发送"触发回零"命令到电机
   ├─ 收到电机 02 应答 → 转发上位机【回零已启动】
   ├─ 收到电机 9F 应答 → 转发上位机【回零成功】→ 进入 IDLE
   ├─ 收到电机 E2/EE/12 → 转发上位机【回零失败+错误码】→ 进入 ERROR + 本地停止
   └─ 超时未收到任何应答 → 转发上位机【电机通信异常】→ 进入 ERROR
```

### 4.0.2 链路 B：指令送达确认（每条上位机命令都走）

```
上位机命令到达主控
 → 主控校验命令合法性（状态是否允许、参数是否合理）
   ├─ 合法 → 转换为 CAN 命令发电机
   │         ├─ 电机回 02 → 转发上位机【电机已接收】
   │         ├─ 电机回 E2/EE → 转发上位机【电机拒绝+原因】
   │         └─ 超时无应答 → 转发上位机【电机通信超时】+ 进入 ERROR
   └─ 不合法 → 直接告诉上位机【命令拒绝+原因】
```

### 4.0.3 链路 C：动作完成确认（链路 B 之后）

```
电机正在执行（主控状态 = RUNNING/HOMING/CYCLING）
 ├─ 电机回 9F（到位完成）
 │   → 主控更新状态机
 │   → 转发上位机【动作完成】
 │
 ├─ 电机回 E2（执行中错误，如堵转）
 │   → 主控立即本地响应（停止 + 失能 + 进入 ERROR）
 │   → 转发上位机【动作失败+错误码】
 │
 ├─ 电机定时上报数据（实时位置等）
 │   → 主控解析 → 转发上位机【实时数据】（可整合后批量上报）
 │
 └─ 急停按钮触发（PD15）
     → 主控立即发"立即停止"到电机
     → 进入 ESTOP 状态
     → 转发上位机【急停触发】
```

### 4.0.4 关键设计约束

⚡ **主控不允许私自吞掉电机的任何应答**：02 / 9F / E2 / EE / 12 / 主动上报数据，全部要在主控状态机内被处理，并相应转发上位机。

⚡ **每条上位机命令至少触发 2 次反馈**：一次"电机已接收"（链路 B），一次"动作完成或失败"（链路 C）。读取类命令例外。

⚡ **错误必须双重处理**：主控本地立即响应（保护设备）+ 同步告知上位机（让上位机知道）。两者不可缺一。

⚡ **未匹配请求的孤立应答帧**（如定时返回的数据）：必须能识别并按"数据透传"处理，不要当成错误。

⚡ **超时机制必须存在**：发命令给电机后，若超过设定时间（建议 200ms~500ms）没收到任何应答，必须视为通信异常。

### 4.0.5 实现要点提示

💡 建议在主控内部为每条发往电机的命令维护一个"待应答记录"（功能码 + 时间戳），收到应答时按功能码匹配。
💡 上位机应答帧建议设计为带"事件类型"字段，区分"指令送达确认"、"动作完成"、"实时数据"、"错误"、"异步事件"五类。
💡 电机的 Response 模式和定时返回参数，应在主控初始化时统一配置，不要依赖电机出厂默认值。

## 五、项目要求简述

### 5.1 核心工艺动作需求（执行能力）

- **精准回零**：上电后自动触发（链路 A）
  - ✅ ZDT 驱动已封装回零函数
  - 💡 无限位碰撞回零已足够，两段式可暂不实现

- **送料与定位**：按设定长度精准送料、点位定位、多工位切换
  - ✅ 直接调用已封装函数（注意接 Both 模式应答处理）

- **节拍运行**：多点往返循环，可设定停留时间与循环次数
  - 💡 二次封装为新函数，注意每点的完成判断要走链路 C

- **平滑运动规划**：梯形加减速
  - ✅ ZDT 电机已支持

### 5.2 异常保护需求

- **位置限位**：硬限位 💡 暂不需要；软限位 ✅ 由无限位碰撞回零实现
- **电机异常保护**：堵转/过流/过温 ✅ 电机内置，主控通过 0x3A 读取标志位响应
- **跟随误差报警**：✅ 电机支持，调用对应函数读取 + 阈值判断

### 5.3 上位机与人机交互需求

✅ 上位机功能由另一位队友负责，**主控只需预留接口并实现上述链路 B/C 的反馈**。
✅ 当前协议未规定，主控侧先做简单实现，后续调整。

需要预留：
- 状态/曲线数据透传（来自链路 C 的实时数据）
- 参数配置（封装为对应上位机指令调用 X_V2 函数）
- 配方管理（上位机维护数据，主控接收执行）
- 错误码透传（链路 B/C 的失败反馈）

## 九、核心难点

### 难点一：⚡ 三条交互链路的完整实现（最关键）
详见第四章。

### 难点二：数据流梳理
- 上位机 ↔ 主控 ↔ 电机 之间涉及 CAN、USART DMA
- 电机收到命令和完成命令都会返回
- 电机还会主动定时上报
- 主控同时要：实时处理电机应答（紧急响应）+ 转发数据（给上位机）+ 接收上位机指令

💡 合理利用 FDCAN 中断 + USART DMA + TIM6 周期任务；不够可加新机制。

### 难点三：驱动库二次封装
💡 把 X_V2 函数包装为业务动作，避免过度复杂。
