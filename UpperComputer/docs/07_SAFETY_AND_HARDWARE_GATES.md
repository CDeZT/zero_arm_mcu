# 安全与硬件审查门

## 1. 基本事实

- 软件 STOP 是普通通信命令，不是安全认证急停。
- USB断线、PC卡死或GUI崩溃时，软件无法保证命令送达。
- J2/J3等重力轴失能可能快速下落。
- 当前电机方向、机械零点、减速比和软限位仍需装机确认。
- 3D预览和碰撞提示不代表机械安全认证。

## 2. 命令分级

| 等级 | 命令 | 默认权限 |
|---|---|---|
| R | HELLO、GET_STATE、能力、PING | 可执行 |
| S | 烧录、verify、reset | 板卡范围确认后可执行，不产生机械动作 |
| A | STOP、CLEAR_FAULT | 仍属于动作状态变更，真实板测需说明 |
| B | SET_JOINT_TARGET、ENABLE、HOME | 必须机械安全确认 |
| C | DISABLE、TEACH_START/STOP | 可能松轴，必须支撑和掩码确认 |
| D | 轨迹、Cartesian、模型策略动作 | 必须前级验收通过 |

STOP列为A不是因为它危险，而是“发送STOP”可能改变当前运行状态，且不能借
测试STOP为理由先启动不安全运动。

## 3. GUI安全交互

- 危险按钮显示轴掩码、目标、速度和状态。
- Arm有短时效，例如5秒；超时自动取消。
- Arm不持久化，不因重连恢复。
- 连续点动按住运行，松开、失焦、Esc、断线立即停止发送。
- DISABLE/TEACH对重力轴显示单独确认文本。
- 轨迹回放先完整离线验证，再倒计时。
- 状态超过阈值未更新时禁用新动作。
- 命令超时显示“结果未知”，不显示“失败所以可安全重试”。

## 4. 软件检查不替代机械检查

SafetyGate只能检查软件已知信息。以下必须人工确认：

- 机械臂牢固安装。
- 支撑、制动、配重。
- 急停和断电路径。
- 工作空间无人、无障碍物。
- 电机地址与关节对应。
- 正方向。
- 零点和限位。
- 测试速度/角度。

## 5. 动作测试审批模板

```text
测试名称：
允许轴：
起始姿态：
目标/最大变化：
最大速度：
持续时间：
支撑/制动：
急停/断电：
观察反馈：
异常停止条件：
用户确认原文：
```

Agent只执行批准模板中的范围。批准J1测试不授权J2或整条轨迹。

## 6. TEACH额外门槛

```text
[ ] 选定轴已列出
[ ] J2/J3等重力轴有可靠支撑
[ ] 已验证电机失能后0x36继续更新
[ ] TEACH_STOP不自动ENABLE
[ ] 最终actual同步为参考目标
[ ] 重新ENABLE不会追赶旧目标
```

其中“失能后反馈”首次验证本身就有机械风险，应先用非重力轴或拆除负载台架。

## 7. 应用崩溃策略

- 尽力停止本地调度和关闭Transport。
- 如果通信仍可用，可以按经审批策略发送一次STOP；此策略必须测试。
- 不承诺崩溃时STOP一定到达。
- 下次启动显示上次会话异常结束，并首先只读同步状态。

未来若需要失联保护，应在MCU实现经过验证的command lease/watchdog，而不是
仅靠GUI心跳。
